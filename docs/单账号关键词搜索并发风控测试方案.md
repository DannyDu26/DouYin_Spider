# 单账号关键词搜索并发风控测试方案

## 1. 测试目标与边界

本方案用于在独立测试实例中，评估一个已授权抖音账号执行固定关键词搜索时的并发承受范围。测试结果只代表以下负载模型：固定关键词、每个工作协程每秒最多一次请求、并发阶梯逐级升高。

测试脚本只调用本项目 FastAPI，不读取数据库 Cookie，不启动或停止服务，不执行自动重试，也不包含代理轮换、验证码处理、Cookie 轮换或其他风控规避能力。首次检测到明确风控后立即停止施压。

仅允许使用自有或明确授权的账号，并遵守平台规则。不要使用生产主账号或包含多个账号的生产实例。

## 2. 准备独立测试实例

为测试创建专用环境文件和专用 `CRAWLER_PROJECT_ID`。该项目下必须只有一条 `douyin_api_account_v1` 账号记录，包括无效或冷却账号在内也不能存在第二条记录。不要为准备测试而删除生产凭证。

关键配置示例：

```dotenv
APP_ENV=dev
# 示例值；请使用不会与现有环境重叠的专用正整数
CRAWLER_PROJECT_ID=2201

MAX_CONCURRENT_REQUESTS=10
MAX_CONCURRENT_REQUESTS_PER_ACCOUNT=10
ENABLE_TEST_ACCOUNT_PINNING=false
ACCOUNT_ACQUIRE_TIMEOUT_SECONDS=30
ACCOUNT_COOLDOWN_SECONDS=300
```

使用单 worker、单实例启动服务：

```powershell
$env:APP_ENV_FILE = "E:\secure-config\douyin-concurrency-test.env"
python -m uvicorn main:app --host 127.0.0.1 --port 5000 --workers 1
```

完成扫码登录后，先人工检查：

```powershell
Invoke-RestMethod http://127.0.0.1:5000/api/health
Invoke-RestMethod http://127.0.0.1:5000/api/v1/douyin/auth/accounts
```

健康检查中的 `max_concurrent_requests` 和 `max_concurrent_requests_per_account` 均应不小于 10；账号列表应恰好只有目标账号，状态为 `available`。脚本会再次强制检查这些条件，任何一项不满足都不会发送搜索请求。

## 3. 执行测试

默认并发阶梯为 `1、2、3、5、8、10`，每阶段 60 秒，每个工作协程每秒最多一次请求，阶段间冷却 120 秒，停止施压后被动观察账号状态 300 秒。

```powershell
python -m scripts.test_account_concurrency `
  --base-url http://127.0.0.1:5000 `
  --account-id test-account `
  --query "测试关键词"
```

调整参数的示例：

```powershell
python -m scripts.test_account_concurrency `
  --base-url http://127.0.0.1:5000 `
  --account-id test-account `
  --query "测试关键词" `
  --levels 1,2,4,6 `
  --stage-seconds 30 `
  --rps-per-worker 0.5 `
  --cooldown-seconds 180 `
  --observation-seconds 600 `
  --request-timeout 45 `
  --output-dir E:\test-reports\douyin-account-01
```

并发阶梯必须为严格递增的正整数。测试实例的两个并发配置必须不小于最高阶梯，否则预检失败。`--base-url` 不允许包含用户名、密码、查询参数或 URL 片段。

## 4. 自动停止条件

以下任一明确风控信号出现时，脚本立即停止创建新搜索请求：

- API 返回 HTTP 429 或 `UPSTREAM_RISK_CONTROL`；
- API 返回 HTTP 403；
- 账号进入冷却，或 API 返回 `NO_AVAILABLE_ACCOUNT`；
- 搜索响应中的实际 `account_id` 不是目标账号。

以下情况按普通异常退化停止，不视为已经确认风控：

- 连续三次网络错误或 HTTP 502；
- 最近 20 次请求的错误率达到 5%；
- 某阶段成功率低于 99%；
- 某阶段 P95 延迟超过并发 1 基线的三倍。

脚本不重试失败请求。按 `Ctrl+C` 中断时会尽力保存已经完成的请求记录。

## 5. 报告与判定

默认报告目录为 `reports/account-concurrency/<时间戳>/`：

- `requests.csv`：逐请求阶段、配置并发、实际在途数、时间、延迟、状态码、脱敏应用错误码、结果分类、账号 ID 和请求 ID；
- `summary.json`：测试配置、阶段 RPS、成功率、P50/P95、建议安全上限、触发阶段、停止原因和观察期账号状态。

报告不保存关键词明文，只保存关键词长度和 SHA-256；不会保存响应正文、Cookie 或登录凭证。

`safe_level` 是完整通过的最高并发阶梯，`trigger_level` 是首次停止的阶梯：

- `confirmed_risk_control=true`：检测到明确风控，可将触发阶梯视为本轮负载模型下的风险边界；
- `stop_kind=degradation`：只确认发生异常或性能退化，不能宣称已经测到平台风控阈值；
- 所有阶梯通过：只能说明阈值高于本次最高阶梯，不应未经评估继续提高并发。

生产配置不应贴近触发阶梯，建议基于多次独立测试的最低安全值继续预留至少 30% 余量。

退出码：

| 退出码 | 含义 |
| --- | --- |
| 0 | 全部阶梯完成，未检测到风控 |
| 2 | 检测到明确风控 |
| 3 | 账号隔离或服务配置检查失败 |
| 4 | 普通异常达到停止阈值 |
| 130 | 用户中断 |

## 6. 测试后恢复

1. 停止独立测试实例，不要在账号仍处于验证或冷却状态时继续请求。
2. 保留 CSV、JSON 和服务端对应 request ID 日志，用于复盘；不要导出 Cookie。
3. 至少观察账号 24 小时，确认没有延迟出现的安全验证或登录异常。
4. 将常规环境中的并发配置恢复为低并发默认值：

```dotenv
MAX_CONCURRENT_REQUESTS=2
MAX_CONCURRENT_REQUESTS_PER_ACCOUNT=1
ENABLE_TEST_ACCOUNT_PINNING=false
```

5. 重启常规实例，并通过 `/api/health` 确认并发配置已经恢复。
