# 浏览器抖音与小红书登录同步

扩展支持手动把当前 Chrome 配置中的抖音或小红书登录 Cookie 发送到本项目服务端。选择平台后展开“同步登录到服务端”，无需重新扫码，但服务端必须能通过对应平台的正式用户校验。

## 配置与使用

1. 服务端启用对应平台和数据库。小红书还需完成 `crawler_cookie.remark` 的 TEXT 迁移。
2. 在实际使用的 `.env.dev` 或 `.env.prod` 配置随机生成的长 ASCII 密钥：抖音为 `DOUYIN_COOKIE_IMPORT_TOKEN`，小红书为 `XHS_COOKIE_IMPORT_TOKEN`，然后重启服务。留空时关闭该平台的导入接口，返回 503。
3. Chrome 重新加载 `douyin-chrome-extension` 目录，打开对应平台的已登录标签页。
4. 在插件选择“抖音”或“小红书”，展开同步表单，填写账号别名和对应密钥，再点击“同步当前登录”。服务地址固定为 `https://crawler.xoyo.com/`，界面会展示该接收方，无需填写地址。
5. 首次同步授权 `https://crawler.xoyo.com/` 的网站访问权限。看到“已验证并保存”表示服务端正式用户校验、数据库保存与账号入池已完成。

相同平台的相同账号别名会更新已有凭证；两个平台分别保存别名，切换平台清空密钥。使用前请确认当前浏览器登录的是预期账号。

如果同步提示缺少 `a1` 或 `web_session`，先重新加载扩展并刷新已登录的小红书页面。同步读取覆盖接口 URL、当前页面路径和小红书主域；接口未读到 `a1` 时从当前页面补充。`web_session` 仍必须通过 Cookie API 读取。错误信息会分别列出缺少的字段和已读取的 Cookie 名称，不显示值；如果仍失败，可提供这段提示用于排查，无需复制 Cookie 内容。

抖音读取当前 Store 的 `sessionid` 等登录字段。缺少 `s_v_web_id` 时先从当前页面读取，再沿用采集客户端的备用指纹；只补充接口指纹，不生成登录会话。服务端调用当前用户接口，只有返回有效正式用户 ID 才保存。验证失败保留旧账号，数据库失败不入池；同一账号重复同步返回 409，同时最多处理两个抖音同步任务。

## 接口

基础地址固定为 `https://crawler.xoyo.com`，使用 POST 和 `Content-Type: application/json`。

| 平台 | 接口路径 | 鉴权请求头 | 密钥环境变量 |
| --- | --- | --- | --- |
| 抖音 | `/api/v1/douyin/auth/cookie/import` | `X-Douyin-Import-Token` | `DOUYIN_COOKIE_IMPORT_TOKEN` |
| 小红书 | `/api/v1/xhs/auth/cookie/import` | `X-XHS-Import-Token` | `XHS_COOKIE_IMPORT_TOKEN` |

请求体示例（均为占位值）：

```json
{"account_id":"xhs_01","cookie":"a1=<真实设备标识>; web_session=<真实登录会话>; webBuild=<浏览器值>"}
```

抖音请求体同样包含 `account_id` 和 `cookie`，Cookie 示例：`sessionid=<真实登录会话>; s_v_web_id=<接口指纹>`。

成功使用项目统一响应，`data.status` 为 `succeeded`，包含 `account_id`；小红书额外包含 `session_id`。响应不返回 Cookie。失败使用统一错误结构；缺少或错误密钥返回 401，未启用返回 503，参数错误返回 422；上游登录过期或安全验证按对应平台的错误分类返回。

## 传输与保存

扩展通过 `chrome.cookies` 读取当前标签页所属 Cookie Store，包括 HttpOnly Cookie；只发送所选平台域名的 Cookie，不混用其他平台或 Store，也不发送分区 Cookie。接收方固定为 `https://crawler.xoyo.com/`，可选网站权限仅声明此站点；旧版本保存的地址会被清理。上传不跟随重定向，代理应直接提供上述 POST 路由。扩展页面通过已授权的网站权限请求服务，不需要给普通网页开放跨域访问。

仅账号别名保存在扩展本地设置，密钥只保留于当前侧边栏，Cookie 不写入扩展存储。同步只由按钮触发，不随登录状态变化自动上传。服务端按现有机制将 Cookie 和运行状态写入 `crawler_cookie`，当前存储机制不是应用层加密；数据库访问与保存期限由服务管理员管理。卸载扩展不会删除服务端凭证，需联系服务管理员清理相应账号记录并刷新账号池。

独立同步密钥是具有写入权限的凭证，应仅发给允许同步账号的使用者，通过环境变量配置；不要提交到代码库或嵌入扩展包。反向代理也应避免记录请求头中的密钥和请求体。

## 限制与验证

浏览器登录有效仍可能因服务端网络、设备环境或平台验证而导入失败。当前导入传输 Cookie，服务端使用项目已有签名与状态初始化，不复制浏览器的全部 localStorage、设备指纹或网络环境。导入成功确认正式用户接口可用；各数据接口仍可能出现独立的访问限制。抖音 Cookie 同步不包含扫码登录的 Ticket、私钥或证书，依赖这些额外凭证的接口可能仍需扫码登录。

测试使用模拟浏览器 API、模拟上游用户校验和内存 SQLite，不读取真实 Cookie、不发送真实上传。真实联调需要用户配置服务并点击同步。发布扩展前需更新公开隐私政策与商店数据使用披露；仓库政策文件的修改不会自动更新已上线网页。
