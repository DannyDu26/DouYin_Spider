# 多账号关键词搜索并发风控测试方案

## 1. 测试目标与安全边界

本方案用于测试自有或明确授权的多个抖音账号。脚本固定关键词、每个工作协程按设定 RPS 发起请求，不读取 Cookie、不重试、不处理验证码，也不提供代理或凭证轮换能力。任一账号出现明确风控时，默认立即停止全部账号的新请求。

多账号测试分为两种模式：

- `sequential`：逐账号执行完整阶梯，适合比较各账号自身的安全并发，推荐先执行。
- `simultaneous`：多个账号同步执行阶梯，适合观察共享 IP、运行环境和账号池的整体影响。

## 2. 独立测试实例

使用专用 `CRAWLER_PROJECT_ID`，该项目下的账号集合必须与命令中的 `--account-ids` 完全一致。不要在生产实例开启账号定向能力。

两个账号同时按每账号最高并发 3 测试时，可使用：

```dotenv
APP_ENV=dev
CRAWLER_PROJECT_ID=2202
MAX_CONCURRENT_REQUESTS=6
MAX_CONCURRENT_REQUESTS_PER_ACCOUNT=3
ENABLE_TEST_ACCOUNT_PINNING=true
ACCOUNT_ACQUIRE_TIMEOUT_SECONDS=30
ACCOUNT_COOLDOWN_SECONDS=300
```

使用单 worker 启动独立实例：

```powershell
$env:APP_ENV_FILE = "E:\secure-config\douyin-multi-account-test.env"
python -m uvicorn main:app --host 127.0.0.1 --port 5001 --workers 1
```

运行前检查：

```powershell
Invoke-RestMethod http://127.0.0.1:5001/api/health
Invoke-RestMethod http://127.0.0.1:5001/api/v1/douyin/auth/accounts
```

健康检查中的 `test_account_pinning_enabled` 必须为 `true`。全部目标账号必须为 `available`，且实例中不能混入其他账号。

## 3. 逐账号测试

逐账号模式在同一时间只对一个账号施压。每个账号会先执行一次定向冒烟请求，然后依次执行全部阶梯。

```powershell
python -m scripts.test_multi_account_concurrency `
  --base-url http://127.0.0.1:5001 `
  --account-ids account-a,account-b `
  --query "剑网3" `
  --mode sequential `
  --levels 1,2,3
```

此时全局并发和单账号并发均需不低于最高阶梯。`concurrency-scope` 在逐账号模式下不改变调度方式。

## 4. 同时测试

`per-account` 表示阶梯值作用于每个账号。两个账号执行阶梯 3 时，总并发为 6：

```powershell
python -m scripts.test_multi_account_concurrency `
  --base-url http://127.0.0.1:5001 `
  --account-ids account-a,account-b `
  --query "剑网3" `
  --mode simultaneous `
  --concurrency-scope per-account `
  --levels 1,2,3
```

`total` 表示阶梯值是账号池总并发，脚本会按阶段轮转并尽量均匀分配：

```powershell
python -m scripts.test_multi_account_concurrency `
  --base-url http://127.0.0.1:5001 `
  --account-ids account-a,account-b `
  --query "剑网3" `
  --mode simultaneous `
  --concurrency-scope total `
  --levels 2,4,6
```

可继续使用 `--stage-seconds`、`--rps-per-worker`、`--cooldown-seconds`、`--observation-seconds`、`--request-timeout` 和 `--output-dir` 覆盖默认值。

## 5. 判定和报告

默认报告目录为 `reports/multi-account-concurrency/<时间戳>/`：

- `requests.csv` 同时记录目标账号和服务实际使用账号；两者不一致会立即停止。
- `summary.json` 包含整体阶段指标、每账号阶段指标、每账号安全并发、首个异常账号和观察期状态。
- 报告只保存关键词长度和 SHA-256，不保存关键词明文、响应正文、Cookie 或凭证。

退出码：

- `0`：全部测试阶段完成，未确认风控。
- `2`：任一账号出现明确风控、账号冷却或不可用。
- `3`：账号集合、定向开关、并发配置或账号归属检查失败。
- `4`：普通异常率、连续异常、成功率或延迟达到退化停止条件。
- `130`：用户中断，仍保存已有报告。

`group_safe_level` 只表示所有目标账号在对应调度模式下共同完整通过的阶段。某账号在阶段 3 触发风控时，其他账号只能认定完整通过此前阶段，不能据此认定它们也在阶段 3 触发风控。

## 6. 测试后恢复

停止独立实例，并恢复常规配置：

```dotenv
MAX_CONCURRENT_REQUESTS=2
MAX_CONCURRENT_REQUESTS_PER_ACCOUNT=1
ENABLE_TEST_ACCOUNT_PINNING=false
```

重新启动服务并检查健康响应确认配置已生效。测试阈值只适用于本次关键词、RPS、账号组合和网络环境，生产配置应预留安全余量。
